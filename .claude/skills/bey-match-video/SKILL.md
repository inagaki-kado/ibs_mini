# 対戦動画の編集ルール

板橋ベイブレード会の大会・SITリーグの収録動画を編集するときの決まりごと。
**ここに書いた方針はユーザー（稲垣）と合意済み。毎回これに従い、変えるときはユーザーに確認する。**

ffmpeg は入っていない。macOS の Swift / AVFoundation で作った `tools/` のツールを使う。

## 1. 編集方針（ユーザー合意済み）

### 残すもの
- **NEXT BATTLE（〇〇 vs 〇〇）の画面は全部残す。** 会場のガヤが主役なので削らない
- **各バトルは、両者がベイを見せ合う瞬間の約1秒前から始める**（シュートの1秒前ではない）
  - 画面下にベイ名が表示されるタイミングを手がかりにする（`analyze` の `pld`/`prd`、`plan.py` の BEYNAME）
  - 名前の表示は見せ合いより少し遅れることがあるので、静止画で手が入ってくる瞬間を確かめる
- 決まり手の表示（XTREME / OVER / BURST / SPIN FINISH）は、表示されてから約3秒後まで残す
- 次のバトル開始までの間が5秒未満なら、カットせずにそのままつなぐ
- **ジャッジの説明など、意味のある会話は切らない**（例: 再試合になった理由を言うところまで残す）
- **締めは、実況が対戦成績を言い終えて会場が盛り上がるところまで続ける**（結果表示から＋30秒程度）
- 冒頭は、会場の様子や NEXT BATTLE が始まるあたり（ユーザーの指定があればそれに従う）から

### カットするもの
- 準備中・待ち時間（ランチャーの準備、休憩、アプリ操作）は遠慮なくカットする
- アプリが落ちたときの白画面、カメラ許可のダイアログなど、事故の画面
- 長すぎる WINNER 表示は6〜10秒に縮める

### アプリの表示バグへの対処
- WINNER 表示のあとに名前・所属・スコアが化けるなどのバグは、**正しい表示の1コマを `freeze` で固定して隠す**（音声は流れ続ける）
- アプリの結果表が誤表示のときは、**ユーザーから届いた結果画像を `endCard` で差し替える**
- 直しきれない一瞬の化けは残してよいが、報告で必ず伝える

### リプレイ
- **リプレイは、試合の勝敗が決まったバトル（決着の1本）だけに入れる。** 全バトルには入れない
- 0.4倍速。リプレイ中は「◀◀ REPLAY ×0.4」の帯と上下の赤ラインを表示する（ツールが自動で付ける）
- **リプレイ中も元の音声を小さく（30%）流す**（音の高さは保つ）
- 範囲は「実際に決着した瞬間」が入るように選ぶ。決まり手表示はオペレーターの操作で2〜5秒遅れて出る
  - 迷ったら「決まり手表示の約7秒前〜3秒前」を一律で使い、ジャッジの手が入る前に終わっているか静止画で確かめる

### 画面の大きさ（トリミング）
- 書き出しは **1920×1080**
- 縦持ち収録の iPhone 画面（2622×1206）は、**左右のカメラの黒い部分が隠れるまで拡大する**（`zoom: 0.8515`。上下に細い黒帯が入る）
- 黒い部分がない動画なら `zoom: null`（全体を収める）

### BGM
- **ベイブレードエックス公式バトルミュージック**（`assets/BEYBLADEX_BATTLE_MUSIC.mp3`、約63秒、ループして敷く）
  - 出典: https://beyblade.takaratomy.co.jp/beyblade-x/news/news251212.html#music （無料公開。動画での利用条件は未記載）
  - リポジトリは公開なので mp3 はコミットしない（`.gitignore` 済み）。手元にないときは次で取得する
    ```bash
    curl -o "/Users/yamiz/Documents/ベイ会アプリ/.claude/skills/bey-match-video/assets/BEYBLADEX_BATTLE_MUSIC.mp3" \
      "https://beyblade.takaratomy.co.jp/beyblade-x/news/_image/BEYBLADEX_BATTLE_MUSIC.mp3"
    ```
- **音量は「微かに聞こえるくらい」：通常 0.025、リプレイ中 0.08。** 実況・ガヤが常に主役
  - 一度 0.10 / 0.32 で出したら「大きい、1/4に」と言われて今の値になった。上げない

### 作るもの
- SITリーグ：1試合1本
- トーナメント：依頼に応じて「全体」と「準決勝から」の2本など
  - 全体版は、冒頭にトーナメント表を数秒、決勝ステージの前にもトーナメント表を数秒、最後は最終結果画面

## 2. 手順

作業用ファイルはスクラッチパッドに置く。ツールはまずスクラッチパッドにビルドする。

```bash
K="/Users/yamiz/Documents/ベイ会アプリ/.claude/skills/bey-match-video/tools"
B="<スクラッチパッド>/bin"; mkdir -p "$B"
for t in bey_edit frames sheet analyze phone; do swiftc -O "$K/$t.swift" -o "$B/$t"; done
```

1. **動画の場所を確かめる**。ユーザーが添付したパスから移動されていることがある（例: `~/Downloads` → `~/Documents/ベイブレード会/`）。見つからなければ `mdfind -name <ファイル名>`
2. **全体を解析する**（16分で約1.5分、75分で約7分。重いのでバックグラウンドで）
   ```bash
   "$B/analyze" "<動画>" > metrics.csv
   python3 -I "$K/plan.py" metrics.csv
   ```
3. **静止画で構成を把握する**。全体を3秒間隔で抜き出して一覧にし、試合・バトル・NEXT BATTLE・WINNER・バグ画面の時刻を拾う
   ```bash
   "$B/frames" "<動画>" frames/ $(seq 0 3 <長さ>)
   "$B/sheet" frames/ sheet.jpg 8      # 48枚ごとに分けて Read で見る
   ```
   - **時刻は必ず各コマの黄色いラベルで読む。** 行や列を数えて推測すると20秒以上ずれる
   - 細かい境目は `--exact` と0.1〜0.5秒間隔で詰める
4. **segments を組む**（`examples/sit2.json` がひな形）。試合ごとに
   NEXT BATTLE（全部） → 各バトル（見せ合いの1秒前〜決まり手表示の3秒後） → 決着バトルのリプレイ → WINNER（6秒程度） → 次の NEXT BATTLE
5. **プレビューで確かめる**。各バトルの開始直後、リプレイ、拡大トリミング、エンドカードを静止画で見る
   ```bash
   "$B/bey_edit" config.json --preview pv/ 1 60 120 …
   ```
6. **本番を書き出す**（バックグラウンドで。16分の素材で約5分、75分で約20分）
   ```bash
   "$B/bey_edit" config.json
   ```
7. **スマホ確認用を作って送る**（下記「納品」）
8. **報告する**：長さ、構成、リプレイの位置（編集後の時刻）、残したバグ表示、未確認のこと（音は聞けないので音量バランスは未確認、など）

## 3. 納品

- 保存先: `/Users/yamiz/Documents/Adobe/Premiere Pro/26.0/`
- ファイル名の例: `SIT2_highlight_v2_1080p.mp4` / `板橋ベイ会1024_全体_1080p.mp4` / `板橋ベイ会1024_準決勝から_1080p.mp4`
- **ユーザーは出先からスマホで確認することが多い。** 本番と一緒に、スマホ確認用を必ず作って `SendUserFile` で送る
  - 送信上限は **30MiB**。`phone` のビットレートは長さに合わせて決める（`phone.swift` 冒頭の目安）
  - 10分程度なら 854×480 1本。約18分なら 640×360（width 640）。それ以上は約15分ごとに分割して送る
- 元の動画は消さない・上書きしない。古い版を消すときはユーザーに確認し、ゴミ箱へ移す（`osascript` で Finder の delete）
- 書き出し後に残る `*.sb-*` という一時ファイルはゴミ箱へ移す

## 4. 技術メモ

- 縦持ち収録の動画は `preferredTransform` が90°回転。`analyze` と `bey_edit` は自動で補正する
- HEVC の長尺はデコードが重い。`frames` は既定で±0.1秒の許容で速く取る（`--exact` は遅い）
- 決まり手表示は `sat`（中央の彩度）が60を超える。WINNER の枠にも反応することがある
- NEXT BATTLE などの全画面画面は、下部パネル位置の暗さ `lp` と `rp` がともに0.85超
- `phone` の音声は 64kbps 固定。48kbps にするとエンコードに失敗する（"Cannot Encode Media"）
- 素材のダウンロード（BGM 以外の音源・画像など）は、ファイル名・入手元・サイズを伝えて許可を取ってから
- `bey_edit` の `freeze` は、その時刻の1コマを指定秒数だけ止める（音声はその間も元のまま流れる）
